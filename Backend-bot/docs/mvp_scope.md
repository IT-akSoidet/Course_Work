# MVP scope: сервис бронирования аудиторий

## Цель MVP
Собрать рабочий Telegram-бот для бронирования аудиторий с учетом ролей, конфликтов по времени и занятости по расписанию.

## Роли
- `student`:
  - поиск свободных аудиторий;
  - создание заявки на бронь;
  - просмотр и отмена своих броней до начала слота.
- `teacher`:
  - все права студента;
  - повышенный приоритет в конфликтных сценариях.
- `admin`:
  - модерация конфликтных заявок;
  - управление справочниками;
  - импорт расписания занятости.

## Границы данных
- Кампус: НИУ ВШЭ - Нижний Новгород.
- Источник расписания для MVP: CSV-импорт.
- Внешний API расписания: не обязателен в MVP, но предусмотрен интерфейс расширения.

## Бизнес-правила MVP
- Бронь нельзя создавать на прошедшее время.
- Бронь нельзя создавать на интервал, который пересекается с:
  - активной бронью (`pending`, `approved`);
  - занятостью из расписания (`room_unavailability`).
- При конфликте заявки преподавателя и студента:
  - создается `pending`;
  - решение принимает администратор.

## Критерии готовности MVP
- Работают 3 роли и проверка прав.
- Работает базовый сценарий `поиск -> бронь -> просмотр -> отмена`.
- Включена защита от двойного бронирования.
- Учитывается импортированная занятость аудиторий.
